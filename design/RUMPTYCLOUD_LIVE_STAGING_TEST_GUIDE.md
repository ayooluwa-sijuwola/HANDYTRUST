# RumptyCloud live staging test — Windows guide

You'll run HandyTrust on your computer and upload **synthetic test images**, generated by the app itself, to your **RumptyCloud staging bucket**. Then you'll view them in the app, view them again with a fresh link, and delete them.

**What runs where:**

| Part | Where it runs |
|---|---|
| Sign-in, database, server functions | **Local Firebase emulators** on your PC (project `demo-handytrust-media`). Nothing touches a real Firebase project |
| Image files | Your **real RumptyCloud staging bucket** (`handytrust-staging-media`, bucket ID `assets-handytrust-01a0f99e-5d6ffa`) |
| Keys | Only in `functions\.secret.local` on your PC. They never go into the app, Git or any document |

Commands below are for **Windows PowerShell**, run from `C:\PROJECTS\handy_trust`. Use the VS Code terminal or any PowerShell window.

---

## 1. Check the RumptyCloud dashboard (every time, before testing)

1. **Storage → Buckets → `handytrust-staging-media`:** status **READY**, visibility **PRIVATE**. Don't change either.
2. **Billing:**
   - prepaid balance is **$5 or less**;
   - **automatic top-up is OFF**;
   - write the balance down, so you can compare after testing.
3. If any of these isn't true, **stop**: don't upload anything.

## 2. Key permissions (one-time)

Create the keys in the RumptyCloud dashboard under **Access keys**, for the staging bucket only.

| Key | Permissions to tick | Used for |
|---|---|---|
| **Key 1 — app key** (required) | **Read** + **Write** | Uploads, checks, temporary view links |
| **Key 2 — clean-up key** (strongly recommended) | **Delete** (List is optional) | Deleting images and test clean-up |

- Permissions can't be edited after a key is created. If a key is wrong, create a new one and revoke the old one.
- **One key only** is possible, but it must have **Read + Write + Delete**, and the setup script asks you to type `ACCEPT`. It's less safe: one leaked key could read, overwrite and delete everything in the bucket.

## 3. Store the keys on your PC (one-time, or whenever a key changes)

```powershell
cd C:\PROJECTS\handy_trust
powershell -ExecutionPolicy Bypass -File tool\set_rumpty_credentials.ps1
```

- **Typing is hidden:** paste each value when asked; nothing is shown.
- **Success** is the green line **"Saved functions\.secret.local (values not shown)."**, followed by:
  - `Full path: C:\PROJECTS\handy_trust\functions\.secret.local`;
  - the computer name.
- **If the path or computer differs**, you ran it in another copy of the project: run it again in `C:\PROJECTS\handy_trust`.
- **Never paste keys into chat, a document or a code file.** The file is git-ignored.

Optional check, which shows names only and no values:

```powershell
Select-String -Path functions\.secret.local -Pattern '^RUMPTY_[A-Z_]+' | ForEach-Object { ($_.Line -split '=')[0] }
```

You should see four names: `RUMPTY_ACCESS_KEY_ID`, `RUMPTY_SECRET_ACCESS_KEY`, `RUMPTY_CLEANUP_ACCESS_KEY_ID`, `RUMPTY_CLEANUP_SECRET_ACCESS_KEY`.

## 4. Start the Firebase emulators (window 1, keep it open)

```powershell
cd C:\PROJECTS\handy_trust
powershell -ExecutionPolicy Bypass -File tool\start_rumpty_emulators.ps1
```

- **Ready** when you see **"All emulators ready"**, with Auth 9099, Firestore 8090, Functions 5001 and Storage 9199.
- **The script refuses to start** if the key file is missing or incomplete.
- **Your data is kept between runs** in `%USERPROFILE%\handytrust-emulator-data`, so your test records survive a restart.
- **To stop**, press Ctrl+C in this window.

## 5. Start the Android emulator and the app (window 2)

**Start an Android emulator:**

```powershell
flutter emulators --launch Pixel_8
```

- Wait for the Android home screen.
- If it fails with *"Insufficient RAM"*, close other programs. Or start it with less memory:

  ```powershell
  & "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -avd Pixel_8 -memory 2048
  ```

**Start HandyTrust in emulator mode:**

```powershell
cd C:\PROJECTS\handy_trust
powershell -ExecutionPolicy Bypass -File tool\run_handytrust_emulator_app.ps1
```

- **In VS Code** you can instead pick **Run and Debug → "HandyTrust — local emulators (Android emulator)"**.
- **First build** takes a few minutes. The app opens on the emulator.
- **Confirmation:** the debug console shows `[emulator] EMULATOR MODE — project demo-handytrust-media at 10.0.2.2`.
- **If the app refuses to start** with "Emulator mode needs an Android build made with HT_EMULATOR=true…", the build still contained the production config. Stop it and run the script again; the script sets this for you.

**Physical phone over USB, instead of the emulator:**
1. Enable USB debugging on the phone and connect it.
2. Run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File tool\run_handytrust_emulator_app.ps1 -UsbPhone
   ```

   This maps ports 9099, 8090, 5001 and 9199 from the phone to your PC (`adb reverse`), so no Wi-Fi or firewall changes are needed.

> Inside Android, `localhost` is the **phone itself**, not your PC. The Android emulator reaches your PC at `10.0.2.2`, and a USB phone uses `adb reverse`. Both are already set up by the scripts.

## 6. Sign in with a test account (emulator accounts only)

1. On the onboarding screen tap **Skip**, then **Sign Up**, and register with a **made-up** address such as `tester1@example.test`. These accounts exist only in the local emulator.
2. The app asks you to verify the email. The **verification link appears in window 1** (the emulators). Open it in your browser, then return to the app and continue.
3. Complete the profile steps and choose **Customer**.

## 7. Open the test screen

**Profile** tab → **gear icon** (top right) → scroll to **STAGING (EMULATOR ONLY)** → **Media storage test**.

This screen exists only in emulator-mode debug builds, never in normal or release builds.

## 8. Create a synthetic image

1. **Media type:** `test-portfolio` (or `test-avatar`; `test-thumb` makes a small 128 px image).
2. **Image format:** **JPEG**, **PNG** or **WebP**.
3. Tap **Create image**.
   - A coloured square labelled **"SYNTHETIC TEST"** with a timestamp appears, with its size underneath.
   - It's drawn by the app; no photo from your phone is ever used.

## 9. Upload it

Tap **Upload**. The status line shows:

1. Asking the server for an upload…
2. Uploading…
3. Server is verifying the stored file…

**Success** is a green box: *"Stored and verified by the server. Uploaded through the Firebase function (or directly to RumptyCloud). Media id: …"*.

## 10. Confirm the upload

- **In the app:** the image appears under **MY TEST MEDIA** with status **verified**, plus its type, size and dimensions.
- **In the local database** (PowerShell, window 2):

  ```powershell
  Invoke-RestMethod -Headers @{Authorization='Bearer owner'} "http://127.0.0.1:8090/v1/projects/demo-handytrust-media/databases/(default)/documents/media" | ConvertTo-Json -Depth 6
  ```

  Each record shows `status: verified`, an `objectKey` (`staging/media/…`), and `verifiedSha256` equal to `sha256`. There is no link and no key.
- **In RumptyCloud:** the bucket's file browser shows the object under `staging/media/test-portfolio/<year>/<month>/`.

## 11. View the private image

Tap the **eye icon** on the item. The app asks the server for a **temporary link (5 minutes)** and shows the image.

The link is held in memory only; it's never saved.

## 12. Refresh and view again

In the viewer tap **Refresh link**. A new temporary link is fetched and the image loads again; the counter shows how many times. Close and reopen the viewer to repeat.

## 13. Delete the test image

Tap the **bin icon** → **Delete**. On success the message reads *"Deleted from the bucket and confirmed: no longer available."*

- The server removed the object and checked that it's gone.
- The app then asked for the image again, and the server refused.
- The item's status changes to **deleted**.

If deletion can't complete, the message says it's **pending** and the server retries. It never shows success unless the object is really gone.

## 14. Verify clean-up

- **RumptyCloud:** the object no longer appears in the bucket's file browser.
- **Local database:** re-run the command from step 10; the record shows `status: deleted`.
- **Balance:** check it again. If it **dropped unexpectedly**, stop all testing and report it.

## 15. Automated live test run (optional, bounded)

This runs the full automated check against the real bucket:
- key permissions;
- JPEG, PNG and WebP uploads;
- HEAD metadata;
- refreshed reads;
- refusal of other users, anonymous access and listing;
- invalid uploads;
- size, type, ACL and expiry enforcement;
- deletion and clean-up.

**Limits:** at most 30 objects and 25 MB per run. Every object it creates is deleted and checked by key.

Stop the window-1 emulators first, then:

```powershell
cd C:\PROJECTS\handy_trust
powershell -ExecutionPolicy Bypass -File tool\run_rumpty_live_tests.ps1
```

It asks you to confirm the dashboard checks (yes/no), runs, and prints an **Evidence** folder with JSON results (no keys, no links). Check the balance afterwards.

## If something goes wrong

| Message or symptom | What it means | What to do |
|---|---|---|
| "Media storage is not configured on this server." | Keys missing or incomplete, or the emulators were started before the keys were saved | Run step 3, then restart step 4 |
| "Verify your email address to upload media." | The emulator account isn't verified | Open the verification link from window 1 (step 6) |
| "The media service did not respond…" | Emulators not running, or the app can't reach them | Start step 4; for a USB phone use `-UsbPhone` |
| "Upload limit reached…" | Rate or quota limit (10 per 10 min, 50 per day, 3 pending, 100 MB per user) | Wait, or delete test items |
| "The file was rejected" (with a reason) | The server's checks failed (type, size, checksum, structure) | Create a new image and try again |
| "Deletion is pending…" | RumptyCloud refused or failed the delete; the server retries automatically | Check again later; report it if it stays pending |
| Window 1 shows "Unable to access secret … Secret Manager" | Key file missing; the emulator tried Google Secret Manager for the demo project (403, harmless) | Run step 3 and restart the emulators |
| Android emulator "Insufficient RAM" | Not enough free memory | Close programs, or use `-memory 2048` (step 5) |
| Build fails with "not enough space on the disk" | Drive C: is full | Free at least 5 GB |

**Never do this:**
- use real photos;
- run the emulators with `--project handytrust` or `--project staging`;
- share or commit `functions\.secret.local`.
